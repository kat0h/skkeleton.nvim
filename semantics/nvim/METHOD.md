# Neovim の仕様から遷移を数え上げる方法（#268）

Neovim の側から出発して、skkeleton に関わる遷移を漏れなく、ほどよい粒度で数え上げる方法を書きます。親の issue は #268 です。用語は [GLOSSARY.md](../GLOSSARY.md) に合わせます。

この文書は方法だけを決めます。道具はまだありません。§6 の insert の類の表は、`index.txt` の説明を読んで作った案です。子の nvim でキーを流して確かめるのは、道具の段です。

- 数を数えた版: Neovim 0.13.0-dev（`g629e501cd6`）。`nvim --headless -u NONE -i NONE` で数えました。
- 読んだもの: `$VIMRUNTIME/doc/index.txt` の insert、cmdline、terminal の節、`doc/tags`、`:help mode()`、`inventory/keys.md`、`inventory/events.md`、`STATE_MACHINE.md` §0–§1、#264。

## 0. #268 の前提から変えたところ

#268 の本文のうち、次の 5 つを変えました。

1. **`index.txt` を全体の出どころにしない。照合の相手にする。** `index.txt` はコマンドの一覧で、キーの一覧ではありません。数えると次のとおりでした。
   - insert の節のタグつきの行は 98 行（`i_` が 96、`complete_` が 2）。同じタグが 2 回以上出るので、タグの種類は 94 です（`i_CTRL-G_j` と `i_CTRL-G_k` が 3 行ずつ）。
   - タグの無い行が 15 行あります（`CTRL-F`、`CTRL-S`、`CTRL-\ a - z`、`<Space> to '~'`、補完の中の `CTRL-L`、`<CR>`、`other` など。手で数えました）。
   - 行そのものが無いキーがあります（`CTRL-B`、`CTRL-L`、`CTRL-Z`）。
   - `doc/tags` には `i_` で始まるタグが 115 個あり、`index.txt` に無いものがあります。`i_CTRL-\_CTRL-O`、`i_ALT`（Alt つきのキーは `<Esc>` とそのキーとして働く）、`i_<C-PageUp>`、`i_CTRL-R_=` などです。
   - terminal の節は、タグつきの行が 0 行です（文章だけ）。`t_CTRL-\_CTRL-N` と `t_CTRL-\_CTRL-O` は `doc/tags` にだけあります。

   そこで、全体は「文脈 × キーのコード」で決め（§1）、`index.txt` と `doc/tags` は「文書にあるコマンドが、どれかの類に入っているか」を確かめる相手にします（§3）。
2. **イベントは遷移の種類にしない。観測にする。** autocmd のイベントは、キー、API、外からの変化のどれかが起こした変化の知らせです。イベントを刺激として数えると、同じ変化を 2 回数えます。イベントの一覧（150 個）は、類の署名の一部（§2）と、キー以外の刺激の漏れを見つけるための一覧（§3）に使います。
3. **類は、skkeleton を載せない素の Neovim で作る。** 類は「Neovim がそのキーで何を変えるか」で決まり、skkeleton の入力相には依りません。遷移の数は、類と状態クラス（そのモードのもの）の積です。こうすると、類を作る処理は軽く、Neovim の版どうしで比べられます（§5）。
4. **代表のキーは、類ごとに 1 つではなく、類 × 経路ごとに 1 つにする。** 同じ類でも、skkeleton がそのキーを知る道（マッピング、guard、autocmd だけ）が違えば、結果が違います。`<BS>` と `<C-w>` はどちらも「前を消す」ですが、`<BS>` はマッピングが奪い、`<C-w>` は奪いません。経路は Neovim の性質ではないので、類を分ける軸にはせず、類の中の区切りにします（§2.4）。
5. **対象を 2 つの環に分ける。** 第 1 の環は、skkeleton がマッピングを置く文脈（insert、cmdline、terminal とその中のサブモード）です。第 2 の環は、マッピングは無いが状態を抱えうる文脈（`ni`、`nt`、`ntT`、visual / select、`N_WAIT` の normal）です。第 2 の環は相手が normal と visual のコマンド（`index.txt` で 500 行あまり）になるので、同じ方法で、あとから作ります。この文書の表は第 1 の環の insert だけです。

## 1. 遷移の全体（決めること 1）

遷移は「状態クラスで、刺激を受けて、何が変わるか」です。刺激を次の 3 種類に分け、それぞれの全体を機械で作れる一覧で決めます。

### 1.1 キー（文脈 × キーのコード）

**文脈**は、Neovim がキーを待っている場面です。`nvim_get_mode()` の `mode` と `blocking` の組で表します。

- `mode` の値は `:help mode()` の一覧にあるものです（`i`、`ic`、`ix`、`niI`、`c`、`cr`、`t`、`nt`、`ntT` など）。
- `blocking` が真なのは、コマンドの途中で続きのキーを待っているときです。`<C-r>` のあとのレジスタの名前、`<C-v>` のあとの文字、`<C-k>` のあとの 2 文字がこれに当たります（仮定 A1）。この文書では `i+待ち` のように書きます。
- 文脈は、出発の文脈（`i`、`c`、`t`）から幅優先でたどって作ります。キーを 1 つ流して、文脈が変わったら、新しい文脈も数え上げの対象に足します。たどる深さは 3 までにします（`<C-r><C-r>{レジスタ}` が 3 つ）。深さ 3 で終わらないものがあれば、道具は止まって知らせます。
- insert の文脈は `i`、`i+待ち`（どのキーのあとかで 5 つ：`<C-v>`、`<C-k>`、`<C-r>`、`<C-g>`、`<C-\>`）、`ix`、`ic` です。

**キーのコード**は次の集まりです。どれも機械で作ります。

| 集まり | 中身 | 数 |
|---|---|---|
| 1 バイト | `0x00`–`0x7f` | 128 |
| 名前のあるキー | `:help key-notation` の表の名前と、`index.txt` に出るマウスとホイールの名前。`nvim_replace_termcodes` が別のバイト列に変えたものだけを採る | 道具で数える |
| 修飾つき | `S-`、`C-`、`M-`、`D-`、`C-S-` と、土台のキーの代表（英字、数字、記号、`<Space>`、`<CR>`、`<Tab>`、`<BS>`、`<Esc>`、矢印、`<F1>`） | 5 × 10 |
| 複数バイトの文字 | `あ`（`index.txt` の「Meta characters … not used」の行） | 1 |

修飾つきは全部を作れないので、代表にします。分け方の根拠は、Neovim が修飾を 1 バイトに畳むかどうか（`<C-a>` は `0x01`）と、guard の判定（`keys.md` §4 の `KS_MODIFIER` の行）です。`vim.fn.keytrans` で畳まれ方を確かめ、同じ畳まれ方のものを 1 つにします（仮定 A3）。

### 1.2 API とコマンド（キーを通らない変化）

ほかのプラグイン、タイマー、`<Cmd>` のマッピング、LSP が、skkeleton の状態を抱えている間に Neovim を変えるものです。全体は `vim.fn.api_info().functions`（263 個）と組み込み関数、Ex コマンド（`index.txt` で 564 行）です。

これらは新しい類を作りません。キーの類と同じ署名（§2）のどれかを、経路「キーが来ない」で起こすものとして扱います。API は 1 つずつ流さず、表（`semantics/nvim/api.lua`）で署名に割り当てます。割り当ての値は「テキスト」「カーソル」「ウィンドウ・バッファ」「モード」「キーを差し込む」「関わらない」です。Ex コマンドは第 2 の環で扱います。

### 1.3 外からの変化

キーも API も通らない変化です。terminal のジョブの出力、フォーカス、画面の大きさ、ファイルの外からの書き換え、貼り付け、サスペンド、終了です。全体の一覧は別に持たず、イベントの一覧から逆に作ります。§3 の確かめ 3 で、どのキーの類でも出なかったイベントは、API の表かこの表のどちらかに書かないと通らないようにします。

## 2. 類を分ける軸（決めること 2）

### 2.1 skkeleton が頼っている観測

`STATE_MACHINE.md` §0 の 3 層ごとに、skkeleton が Neovim の何を読んでいるかを並べます。

| 層 | skkeleton が読むもの | 根拠 | 軸 |
|---|---|---|---|
| 1. Vim のモード | `ModeChanged` の `old_mode` / `new_mode`、`mode()`、`InsertLeave` が出るかどうか（`<C-c>` は出さない） | `events.md` の `ModeChanged` の表、`N_WAIT` | M |
| 2. 入力相 | 入力相は skkeleton の中にあり、Neovim は直接変えない。変わるのは、キーがマッピングに届いたとき、guard（`vim.on_key`）が見たとき、autocmd が走ったときだけ。だから「次のキーがマッピングを通るか」が効く | `keys.md` §1、§4 | W と経路 |
| 3. 表示 | pre-edit の置き場所。insert は extmark（バッファ、行、桁）、cmdline と terminal は本物の文字。壊すのは、テキストの変化（`TextChangedI` / `TextChangedP` / `CmdlineChanged`）、カーソルの移動（`CursorMovedI`）、ウィンドウとバッファの切り替え（`WinLeave` / `BufLeave`）、補完のメニュー（`CompleteDone`） | `events.md` の登録の表の 3–5 行 | P |

### 2.2 軸と値

類は、M、P、W の値の組です。

**M（モード）**：前の文脈の組 → 後の文脈の組。insert から抜けるときは、`InsertLeave` が出るかどうかも値に入れます。文脈の組は `i`、`i+待ち`、`ix`、`ic`、`ni`、`n`、`R`、`v/s`、`c`、`cr`、`t`、`nt`、その他（`no`、`r`、`!`）です。`:help mode()` の値は、どれもこの組のどれかに入れます。入らない値が出たら、道具は止まります。

**P（置き場所）**：pre-edit の置き場所に効く変化。値は次の 10 個です。

| 値 | 意味 |
|---|---|
| なし | テキストもカーソルも変わらない |
| 表示だけ | スクロールだけ |
| カーソル | 同じバッファの中でカーソルが動く |
| 足す | カーソルの位置にテキストが入る |
| 改行 | 行が割れ、カーソルが次の行に移る |
| 前を消す | カーソルの前のテキストが消える |
| 後ろを消す | カーソルの後ろのテキストが消える |
| 行をずらす | 行の頭（字下げ）が変わり、カーソルの桁がずれる |
| メニュー | 補完のメニューが開く、選ぶ先が変わる、閉じる（テキストも変わりうる） |
| ウィンドウ | いまのウィンドウかバッファが変わる |

テキストの変化を「足す」「前を消す」「後ろを消す」「行をずらす」「改行」に分けるのは、pre-edit がカーソルの位置にあり、変化がその前か後ろか同じ行かで、確定済みの文字と pre-edit の関係が変わるからです。同じクラスで結果が割れなければ、道具の段でまとめます（GLOSSARY の「粒度は観測で決めます」と同じ決まり）。

**W（待ち）**：次のキーの行き先。

| 値 | 意味 |
|---|---|
| なし | 次のキーはふつうに処理される |
| 続きを待つ | Neovim が続きのキーを待つ。次のキーはマッピングを通らない（仮定 A2） |
| 回す | サブモードを抜けて、同じキーを別の文脈でもう一度処理する（補完の中の「other」、Alt つきのキー） |

### 2.3 署名（道具が測るもの）

道具は、キーを 1 つ流す前と後で次を記録します。これが署名です。軸の値は、署名から決まった関数で作ります。人が類を選ぶことはしません。

- `nvim_get_mode()` の `mode` と `blocking`
- `changedtick` の差と、テキストの差の種類（足す、消す、どこで）
- カーソルの行と桁、ウィンドウの番号、バッファの番号、`winsaveview()` の `topline`
- `pumvisible()`、`complete_info({"mode"})`
- cmdline では `getcmdtype()`、`getcmdline()`、`getcmdpos()`
- 出たイベントの名前と順番（150 個の全部に、記録するだけの autocmd を置く）
- typeahead が空かどうか（`getchar(1)`）

場面は 2 つにします。効き方が出る場面（3 行の英単語のバッファの 2 行目の行の途中、ウィンドウが 2 つ、直前に挿入したテキストがある、レジスタ `a` に文字がある）と、出ない場面（空のバッファ）です。類は 1 つめの場面の署名で決め、2 つめは「何も起きないことがある」の印にだけ使います。

設定は `-u NONE` の既定にします。設定で類が変わるキー（`'digraph'` の `{char1}<BS>{char2}`、`'cinkeys'` の `<C-f>`、`'allowrevins'` の `<C-_>`、略語があるときの `<C-]>`、`'wildchar'`、`'cedit'`）は、別の表に「設定、キー、変わったあとの類」を書きます。変わったあとの類が既定の類のどれかに入るなら、遷移は増えません。

### 2.4 経路（類の中の区切り）

経路は、skkeleton がその刺激をどの道で知るかです。値は 4 つです。

| 経路 | 意味 | どう決めるか |
|---|---|---|
| map | マッピングが奪う | skkeleton を有効にした子の nvim で、`maparg(キー, モード)` が skkeleton のもの |
| guard 確定 | 奪わないが、guard が確定してから流し直す | `guard._is_physical_special(バイト列)` が真 |
| guard 通す | 奪わず、guard も何もしない | 上の 2 つのどちらでもないキー |
| 来ない | キーではない（API、外からの変化）。知らせは autocmd だけ | §1.2、§1.3 の刺激 |

代表のキーは、類 × 経路の空でない升ごとに 1 つ選びます。選び方は、升の中でバイト列がいちばん短いもの、同じ長さならコードが小さいものにします（機械で決まり、版が変わっても動きにくい）。

## 3. 「漏れなく」の確かめ方（決めること 3）

道具が次の 5 つを確かめ、1 つでも外れたら失敗で終わります。

1. **全域**：§1.1 の文脈 × キーのどの組にも、署名が 1 つ付き、類が 1 つ決まる。軸の値を作る関数が知らない署名（知らない `mode`、知らないイベント、テキストの差の知らない形）が出たら、「その他」に入れずに失敗にする。
2. **文書との照合**：`index.txt` の insert、cmdline の節のすべての行（タグの無い行も含む）と、`doc/tags` の `i_`、`c_`、`t_`、`complete_` で始まるタグのすべてが、表 `semantics/nvim/tags.lua` で「文脈とキーの列」か「キーではない（理由つき）」に割り当てられている。`c_no_utf` のような C の構文のタグ、`t_AB` のような termcap のタグ、`complete_add()` のような関数のタグは「キーではない」にします。割り当てたキーの列は、確かめ 1 で類が決まっていること。
3. **イベント**：`vim.fn.getcompletion("", "event")` のすべてのイベントが、「どれかの類の署名に出た」「API の表にある」「外からの変化の表にある」「関わらない（理由つき）」のどれかである。
4. **文書に無い動き**：類が「文字が入る」でも「何も変えない」でもないのに、確かめ 2 でどのタグにも割り当てられなかったキーを一覧に出す。これは失敗にせず、人が読む。`CTRL-B` のように `index.txt` に行が無いキーは、ここで見つかります。
5. **数の記録**：一覧の大きさを `semantics/nvim/universe.lock` に書く（Neovim の版、`index.txt` の節ごとの行の数とタグの種類の数、`doc/tags` の接頭辞ごとの数、イベントの数、`mode()` の値の数、API の数）。書いてある数と違えば失敗にする。

確かめ 1 は「数え上げた中に漏れが無い」こと、確かめ 2 と 3 は「数え上げの外に、文書やイベントの一覧が知っているものが無い」こと、確かめ 5 は「一覧が黙って変わっていない」ことを見ます。

いまの数は次のとおりです。

| 一覧 | 数 |
|---|---|
| `index.txt` insert：タグつきの行 / タグの種類 / タグの無い行 | 98 / 94 / 15 |
| `index.txt` cmdline：タグつきの行（タグの種類も同じ） | 53 |
| `index.txt` terminal：タグつきの行 | 0 |
| `doc/tags`：`i_` / `c_` / `t_` / `complete_` | 115 / 113 / 15 / 6 |
| イベント | 150 |
| API の関数 | 263 |

## 4. 状態機械と TLA+ への渡し方（決めること 4）

道具は類を `semantics/nvim/classes.json` に書きます。1 つの類は、id、文脈の組、M・P・W の値、入っているキーの全部、経路ごとの代表、割り当てたタグ、署名に出たイベントの順番を持ちます。

**結合の層の状態機械（`semantics/model/model.lua`）へ**

- `M.events` のうち、Neovim が処理するキーのイベントに、類の id を書きます。いまの 93 個のイベントは、類に多対 1 で対応します。
- `model_check.lua` に確かめを足します。あるモードの状態クラスと、そのモードの類 × 経路の升のすべての組に、遷移が 1 つ以上ある。まだ調べていない組は status を `unknown` にして置きます。
- 類 × 経路の升のうち、対応する `M.events` が無いものが、#268 の「進め方」の 3 で issue にする抜けです。
- 遷移の effects は、類からは決めません。類が言うのは Neovim の側の変化だけで、skkeleton が確定するか捨てるかは観測で決めます。

**TLA+（#264 の `Nvim.tla`）へ**

- キーの集まりを、具体のキーではなく類 × 経路の升にします。状態の数が減り、TLC の設定を小さくできます。
- 軸は、そのまま `Nvim.tla` の変数の変え方になります。M は `mode` の次の値、P は「pre-edit の置き場所がまだ有効か」の次の値、W の「続きを待つ」は「次のキーはマッピングを通らない」の旗です。P5（二重に処理しない）に効くのは W と経路です。
- 署名に出たイベントの順番は、#264 が README に書く「Neovim の動きの仮定」の根拠になります。ソースを読んだ根拠に、道具の記録を添えます。
- 類は 1 つのキーの前と後しか見ません。キーの途中の順番（`SafeState`、`vim.schedule`）は類に入らないので、TLA+ の側で書きます。

## 5. Neovim の版が上がったとき（決めること 5）

`classes.json` と `universe.lock` は、基準の版（CI の stable）で作ったものをコミットします。

1. 道具を新しい版（stable が上がったとき、または nightly）で流す。
2. `universe.lock` が違えば、一覧が増減しています。増えたタグ、イベント、`mode()` の値を、§3 の表（`tags.lua`、イベントの表、M の組）に足します。足すまで、確かめ 2 と 3 が通りません。
3. 「文脈 × キー → 類」の対応を、前の版のものと比べます。違いは 3 種類です。
   - 類を移ったキー：Neovim の動きが変わっています。`$VIMRUNTIME/doc/news.txt` をタグで引いて変更を探し、`model.lua` の遷移に版の条件を付け、テストは機能があるかどうかで分けます（AGENTS.md の「テスト」）。
   - 新しい類：新しい署名の組です。状態クラスとの積が `unknown` で増えるので、観測します。
   - 空になった類：消します。
4. 基準の版を上げるときだけ、`classes.json` と `universe.lock` をコミットし直します。nightly の違いはコミットせず、違いが skkeleton の動きに効くときに issue にします。

nightly を毎回流すと重いので、流すのは stable の版が上がったときと、nightly の CI だけが落ちたときにします。

## 6. insert の類の案

`index.txt` の説明から作った案です。36 類あります。道具で署名を測ると、類は増減します。「タグの例」は `index.txt` のタグで、`doc/tags` にだけあるものには †、タグの無い行には ‡ を付けました。

### 文脈 `i`

| # | 類の名前 | M | P | W | 代表のキー | タグの例 |
|---|---|---|---|---|---|---|

## 7. cmdline と terminal

どちらも同じ方法で作れます。

- **cmdline**：出発の文脈は `c` です。`getcmdtype()` で `:`、`/`、`?`、`@`（`input()`。辞書登録の `P_PROMPT`）、`=`（式）を分けます。サブの文脈は `c+待ち`（`<C-r>`、`<C-v>`、`<C-k>`、`<C-\>` のあと）、`cr`（`<Insert>`）、wildmenu の中です。P の値は、置き場所が cmdline の文字になるので、`getcmdline()` と `getcmdpos()` の差で作ります（足す、前を消す、後ろを消す、全部を入れ替える（履歴、`<C-\>e`）、カーソル）。M には「実行して抜ける」「捨てて抜ける」「cmdline window を開く」（`'cedit'`）が加わります。照合の相手は `index.txt` の 53 個のタグと、`doc/tags` の `c_` のタグです。
- **terminal**：出発の文脈は `t` です。`index.txt` に行が無く、文章が「`CTRL-\` 以外のキーはすべてジョブに送る」と言っています。類は少なく、「ジョブに送る」「`<C-\>` で続きを待つ」「`<C-\><C-n>` で `nt` に抜ける」「`<C-\><C-o>` で `ntT` に入る」「`<C-\>` のあとのほかのキーを送る」と、マウスとホイールになる見込みです。照合の相手は `doc/tags` の `t_CTRL-\_CTRL-N` と `t_CTRL-\_CTRL-O` です。terminal では、キーの類よりも、外からの変化（ジョブの出力で行が書き換わる。§1.3）と経路（guard が 1 バイトの制御文字を確定するかどうか。`keys.md` §4）のほうが、分かれ目になります。P は「ジョブがどう答えるか」に依るので、場面のジョブは、受けたバイトをそのまま返すだけのものに固定します。

道具の段で確かめることです。外れたら、この文書を直します。
