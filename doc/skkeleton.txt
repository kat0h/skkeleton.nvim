はじめに                                                *skkeleton-introduction*

*skkeleton.nvim* は Neovim で SKK 方式の日本語入力をするプラグインです。
skkeleton を Neovim 向けに Lua で書き直したものです。
入力中の文字（pre-edit）は、バッファに書かずに extmark の virtual text で
表示します。確定した文字だけがバッファに入ります。

必要なもの~

- Neovim 0.12 で動作を確かめています。
- SKK 辞書。SKK-JISYO.L などを展開して |skkeleton-config-globalDictionaries|
  に書きます。

==============================================================================
インストールと最小の設定                                    *skkeleton-install*

lazy.nvim の例です。
>lua
    {
      "kat0h/skkeleton.nvim",
      event = { "InsertEnter", "CmdlineEnter" },
      config = function()
        require("skkeleton").setup({
          globalDictionaries = { "~/.config/skk/SKK-JISYO.L" },
        })
        vim.keymap.set({ "i", "c" }, "<C-j>", "<Plug>(skkeleton-toggle)")
      end,
    }
<
辞書の DB は、最初に使うときに作ります。起動時に準備するには、|skkeleton-faq|
の |skkeleton-faq-initialize| を見てください。

==============================================================================
Lua API                                                          *skkeleton-api*

すべて `require("skkeleton")` が返す表の関数です。

                                                          *skkeleton.setup()*
setup([{opts}])
	設定します。{opts} のキーは |skkeleton-config| のものです。`indicator`
	だけは |skkeleton-indicator| の設定になります。何度でも呼べます。2 回目
	以降は書いたキーだけを変えます。
	未知のキーや型の違う値があるときは、何も変えずにエラーにします。
	辞書に関する設定は最初に使う前に済ませてください。

                                                         *skkeleton.enable()*
enable()
	SKK を有効にします。|<Plug>(skkeleton-enable)| と同じです。

                                                        *skkeleton.disable()*
disable()
	SKK を無効にします。|<Plug>(skkeleton-disable)| と同じです。

                                                         *skkeleton.toggle()*
toggle()
	有効と無効を切り替えます。|<Plug>(skkeleton-toggle)| と同じです。

                                                           *skkeleton.mode()*
mode()
	今のモードの名前を返します。無効なときは空の文字列です。
	"hira"、"kata"、"hankata"、"zenkaku"、"abbrev" があります。

                                                     *skkeleton.is_enabled()*
is_enabled()
	有効なら true を返します。

                                                       *skkeleton.get_config()*
get_config()
	今の設定の表を返します。書き換えずに読むために使ってください。

                                                      *skkeleton.initialize()*
initialize([{force}])
	初期化して、辞書を UI を止めずに準備します。DB を作る処理は小分けにして
	進めます。{force} が真なら、初期化し直します。
	|skkeleton-initialize-pre| と |skkeleton-initialize-post| のフックは、
	最初の 1 回だけ実行されます。

                                                  *skkeleton.update_database()*
update_database({path} [, {encoding} [, {force}]])
	{path} の辞書の DB を作り直します。
	- {path}: 辞書のパス。
	- {encoding}: 辞書のエンコーディング。省略するか空だと自動で判別します。
	- {force}: 真なら、辞書が変わっていなくても作り直します。
	偽のときは、辞書の大きさか更新時刻が DB の記録と合わないときだけ作り
	直します。

                                                  *skkeleton.register_keymap()*
register_keymap({state}, {key}, {func})
	|skkeleton-kanatable-keymap| を見てください。

                                               *skkeleton.register_kanatable()*
register_kanatable({name}, {tbl} [, {create}])
	|skkeleton-kanatable-register| を見てください。

                                          *skkeleton.register_kanatable_file()*
register_kanatable_file({name}, {path} [, {encoding} [, {create}]])
	|skkeleton-kanatable-file| を見てください。

Vim script の関数として `skkeleton#is_enabled()` と `skkeleton#mode()` だけを
用意しています（ステータスラインから呼ぶためです）。

マッピング                                                *skkeleton-keymappings*

次の |<Plug>| マッピングは挿入モード、コマンドラインモード、端末モード
で使えます。有効なときは、直接入力の状態でだけ働きます。

<Plug>(skkeleton-enable)                             *<Plug>(skkeleton-enable)*
	SKK を有効にします。

<Plug>(skkeleton-disable)                           *<Plug>(skkeleton-disable)*
	SKK を無効にします。

<Plug>(skkeleton-toggle)                             *<Plug>(skkeleton-toggle)*
	有効と無効を切り替えます。
>lua
    vim.keymap.set({ "i", "c", "t" }, "<C-j>", "<Plug>(skkeleton-toggle)")
<
有効なあいだは、次のキーが |skkeleton-functions| に割り当てられています。
|skkeleton.register_keymap()| で変えられます。

input:
	<BS>      |skkeleton-functions-deleteChar|
	<C-g>     |skkeleton-functions-cancel|
	<C-h>     |skkeleton-functions-deleteChar|
	<C-q>     |skkeleton-functions-hankatakana|
	<CR>      |skkeleton-functions-newline|
	<Esc>     |skkeleton-functions-escape|
	<NL>      |skkeleton-functions-kakutei|
	>         |skkeleton-functions-prefix|
henkan:
	<C-g>     |skkeleton-functions-cancel|
	<CR>      |skkeleton-functions-newline|
	<NL>      |skkeleton-functions-kakutei|
	<Space>   |skkeleton-functions-henkanForward|
	x         |skkeleton-functions-henkanBackward|
	X         |skkeleton-functions-purgeCandidate|
	>         |skkeleton-functions-suffix|

                                                       *g:skkeleton#mapped_keys*
g:skkeleton#mapped_keys
	SKK が有効なあいだにバッファローカルで奪うキーの一覧に、足すキーです。
	表記は |<>| の形です。既定のキーは英数字、記号、`<BS>`、`<C-h>`、
	`<CR>`、`<Space>`、`<C-q>`、`<C-j>`、`<C-g>`、`<Esc>` などです。
	足したキーには |skkeleton.register_keymap()| で機能を割り当てられます。
>lua
    vim.g["skkeleton#mapped_keys"] = { "<C-l>" }
    require("skkeleton").register_keymap("input", "<C-l>", "zenkaku")
<
==============================================================================
機能                                                       *skkeleton-functions*

キーに割り当てられる機能です。名前は skkeleton と同じです。括弧は使える
状態と、既定で割り当てたキーです。

kakutei                                          *skkeleton-functions-kakutei*
	(input: <NL>, henkan: <NL>)
	入力中や変換中の文字列を確定します。何も入力していないときは、かな
	入力などのモードを解除します。

newline                                          *skkeleton-functions-newline*
	(input: <CR>, henkan: <CR>)
	今の入力を確定して改行します。確定のあとに改行するかどうかは
	|skkeleton-config-eggLikeNewline| で変えられます。

cancel                                            *skkeleton-functions-cancel*
	(input: <C-g>, henkan: <C-g>)
	今の入力を取り消します。どこまで戻るかは
	|skkeleton-config-immediatelyCancel| で変えられます。

disable                                          *skkeleton-functions-disable*
	(input, henkan)
	SKK を無効にします。

escape                                            *skkeleton-functions-escape*
	(input: <Esc>, henkan: <Esc>)
	挿入モードかコマンドラインモードを抜けます。|skkeleton-config-keepState|
	が真なら、次に入ったときに SKK が有効になります。

henkanFirst                                  *skkeleton-functions-henkanFirst*
	(input)
	変換を始めます。直接入力のときは、かなテーブルの処理をします。

henkanForward                              *skkeleton-functions-henkanForward*
	(henkan: <Space>)
	変換候補を次に進めます。

henkanBackward                            *skkeleton-functions-henkanBackward*
	(henkan: x)
	変換候補を前に戻します。戻りきると入力の状態に戻ります。

purgeCandidate                            *skkeleton-functions-purgeCandidate*
	(input, henkan: X)
	今選んでいる変換候補をユーザー辞書から消します。変換中でなければ、
	直前に確定した候補が対象です。消したときは入力の状態を解除します。

henkanInput                                  *skkeleton-functions-henkanInput*
	(henkan)
	変換候補を確定して、続けて文字を入力します。

kakuteiFeed                                  *skkeleton-functions-kakuteiFeed*
	(input)
	直接入力のときに、確定できる入力があれば確定します（ローマ字の
	「n」が残っているときなど）。

henkanPoint                                  *skkeleton-functions-henkanPoint*
	(input)
	変換ポイントを置きます。いわゆる sticky key です。

deleteChar                                    *skkeleton-functions-deleteChar*
	(input: <BS>, <C-h>)
	入力を 1 文字消します。変換ポイントまで戻ると、それを解除します。

hirakana                                        *skkeleton-functions-hirakana*
	(input)
	ひらがなモードに入ります。

katakana                                        *skkeleton-functions-katakana*
	(input)
	カタカナモードに入ります。変換ポイントがあるときは、カタカナに変換
	します。

hankatakana                                  *skkeleton-functions-hankatakana*
	(input: <C-q>)
	半角カタカナモードに入ります。変換ポイントがあるときは、半角カタカナ
	に変換します。

zenkaku                                          *skkeleton-functions-zenkaku*
	(input)
	全角英数モードに入ります。

abbrev                                            *skkeleton-functions-abbrev*
	(input)
	abbrev モードに入ります。

prefix                                            *skkeleton-functions-prefix*
	(input: >)
	接頭辞の入力を始めます。始められないときは、そのキーをかな入力として
	扱います。

suffix                                            *skkeleton-functions-suffix*
	(henkan: >)
	接尾辞の入力を始めます。

==============================================================================
設定                                                          *skkeleton-config*

|skkeleton.setup()| に表で渡します。キーの名前は skkeleton と同じです。パス
は先頭の `~` だけを展開します。
>lua
    require("skkeleton").setup({
      eggLikeNewline = true,
    })
<
acceptIllegalResult                     *skkeleton-config-acceptIllegalResult*
	(既定: false)
	真にすると、入力に失敗したローマ字がバッファに残ります。

completionRankFile                       *skkeleton-config-completionRankFile*
	(既定: "")
	v1 では使いません。skkeleton の設定をそのまま使えるように、文字列の
	確認だけをします。

databasePath                                   *skkeleton-config-databasePath*
	(既定: "")
	辞書の DB を置くディレクトリです。空なら `stdpath("cache")/skkeleton`
	です。DB は辞書ごとに `<辞書のパスのハッシュ>.db` というファイルです。
	パスがファイルとして存在するか、`skk.db` のように拡張子があるとき
	は、その親のディレクトリを使います。|skkeleton-faq-database| も見て
	ください。

debug                                                 *skkeleton-config-debug*
	(既定: false。|g:skkeleton#debug| が真なら true)
	真にすると、処理するキーなどをメッセージで知らせます。

eggLikeNewline                               *skkeleton-config-eggLikeNewline*
	(既定: false)
	真にすると、変換モードで改行キーを押したときに、確定だけをします。

globalDictionaries                       *skkeleton-config-globalDictionaries*
	(既定: {})
	グローバル辞書です。パスの文字列か、パスとエンコーディングの組の
	配列を並べます。エンコーディングを省くと自動で判別します（EUC-JP と
	UTF-8 を判別できます）。圧縮した辞書は展開してから指定してくださ
	い。拡張子が `.json` の辞書は JSON の辞書として読みます。yaml と
	msgpack の辞書は読めません。
>lua
    globalDictionaries = {
      { "/usr/share/skk/SKK-JISYO.L", "euc-jp" },
      "~/.skk/SKK-JISYO.emoji",
    }
<
globalKanaTableFiles                   *skkeleton-config-globalKanaTableFiles*
	(既定: {})
	複数のかなテーブルを使うときに指定する、かなテーブルのファイルです。
	書き方は |skkeleton-config-globalDictionaries| と同じです。
>lua
    globalKanaTableFiles = { { "/usr/share/skk/azik_us.rule", "euc-jp" } }
<
immediatelyCancel                         *skkeleton-config-immediatelyCancel*
	(既定: true)
	真にすると、候補選択などで |skkeleton-functions-cancel| を使ったとき
	に、一気に未入力の状態へ戻ります。

immediatelyDictionaryRW             *skkeleton-config-immediatelyDictionaryRW*
	(既定: true)
	真にすると、変換と確定のたびにユーザー辞書を読み書きします。Neovim を
	複数動かすときに役立ちます。

immediatelyOkuriConvert             *skkeleton-config-immediatelyOkuriConvert*
	(既定: true)
	真にすると、送りあり変換の途中で「っ」を直接打った時点で、タ行の送り
	仮名が打たれたとみなして変換を始めます。ローマ字の連続入力で「っ」を
	入力するときのように、続く文字があるときには影響しません。

kanaTable                                         *skkeleton-config-kanaTable*
	(既定: "rom")
	使うかなテーブルの名前です。存在するテーブルだけを指定できます。まだ
	無いテーブルを指定するには、先に |skkeleton.register_kanatable()| で
	作ってください。

keepMode                                           *skkeleton-config-keepMode*
	(既定: false)
	真にすると、無効にしても前のモード（カナ入力など）を覚えておきます。

keepState                                         *skkeleton-config-keepState*
	(既定: false)
	真にすると、挿入モードを抜けても前の状態を保ちます。

lowercaseMap                                   *skkeleton-config-lowercaseMap*
	(既定: {})
	かな入力中に大文字を打つと、小文字にして変換ポイントを置きます。かな
	テーブルを変えて記号を割り当てているとうまくいかないので、そのとき
	の変換規則をこの表で指定します。
>lua
    -- AZIK で「っ」を打つための設定
    lowercaseMap = { ["+"] = ";", [":"] = ";" }
<
markerHenkan                                   *skkeleton-config-markerHenkan*
	(既定: "▽")
	変換の入力中を示す文字です。

markerHenkanSelect                       *skkeleton-config-markerHenkanSelect*
	(既定: "▼")
	候補を選んでいる最中を示す文字です。

registerConvertResult                 *skkeleton-config-registerConvertResult*
	(既定: false)
	真にすると、カタカナ変換などの結果もユーザー辞書に登録します。

selectCandidateKeys                     *skkeleton-config-selectCandidateKeys*
	(既定: "asdfjkl")
	候補を選ぶキーです。x 以外の半角英字 7 文字を指定します。

setUndoPoint                                   *skkeleton-config-setUndoPoint*
	(既定: true)
	真にすると、変換と確定のときにアンドゥポイントを切ります。

showCandidatesCount                     *skkeleton-config-showCandidatesCount*
	(既定: 4)
	この数までの候補は、一覧を出さずに 1 つずつ表示して変換します。

skkServerHost                                 *skkeleton-config-skkServerHost*
skkServerPort                                 *skkeleton-config-skkServerPort*
skkServerReqEnc                             *skkeleton-config-skkServerReqEnc*
skkServerResEnc                             *skkeleton-config-skkServerResEnc*
	(既定: "127.0.0.1"、1178、"euc-jp"、"euc-jp")
	v1 では使いません。skkeleton の設定をそのまま使えるように、値の確認
	だけをします。

sources                                             *skkeleton-config-sources*
	(既定: { "skk_dictionary" })
	使う変換元の名前です。ユーザー辞書はこの指定によらず必ず使います。

	"skk_dictionary":
		|skkeleton-config-globalDictionaries| のグローバル辞書で変換しま
		す。辞書は DB にして引きます。
	"deno_kv":
		"skk_dictionary" と同じです。skkeleton の設定をそのまま使えるよう
		に受け付けます。
	"skk_server"、"google_japanese_input":
		v1 では使えません。指定すると警告を出して読み飛ばします。

userDictionary                               *skkeleton-config-userDictionary*
	(既定: "~/.skkeleton")
	ユーザー辞書のパスです。エンコーディングは UTF-8 です。

かなテーブルとキーマップ                                    *skkeleton-kanatable*

                                              *skkeleton-kanatable-register*
register_kanatable({name}, {tbl} [, {create}])
	かな入力のテーブルに規則を足します。{name} のテーブルに、{tbl} の
	規則を登録します。{create} が真でないとき、無いテーブルの名前を指定
	するとエラーになります。{tbl} の値には次のものを使えます。
	- 文字列: |skkeleton-functions| の機能の名前。
	- 1 つか 2 つの文字列の配列: かなの定義。1 つ目が入力するかな、2 つ目
	  がそのあとに続けて入力する文字（省くと空）。「っ」を `tt` で入れ
	  るときなどに使います。
	- false: テーブルからその規則を消します。
>lua
    local skkeleton = require("skkeleton")
    skkeleton.register_kanatable("rom", {
      hh = { "お", "h" },
      jj = "escape",
      ["z,"] = { "―" },
    })
    -- 句読点を全角英字にする
    skkeleton.register_kanatable("rom", {
      [","] = { "，", "" },
      ["."] = { "．", "" },
    })
    -- l で小文字を打てるようにする
    skkeleton.register_kanatable("rom", {
      l = false,
      la = { "ぁ" }, li = { "ぃ" }, lu = { "ぅ" }, le = { "ぇ" }, lo = { "ぉ" },
      lya = { "ゃ" }, lyu = { "ゅ" }, lyo = { "ょ" },
    })
<
                                              *skkeleton-kanatable-file*
register_kanatable_file({name}, {path} [, {encoding} [, {create}]])
	ファイルに書いたかなテーブルの規則を、{name} のテーブルに登録します。
	{encoding} を省くと自動で判別します。

                                              *skkeleton-kanatable-keymap*
register_keymap({state}, {key}, {func})
	状態ごとのキーマップを定義します。{state} は "input" か "henkan" で
	す。{key} は |<>| の形のキーです。{func} は |skkeleton-functions| の
	機能の名前、または Lua の関数です。空の文字列か false を渡すと、その
	割り当てを消します。割り当てたいキーが奪われないときは、
	|g:skkeleton#mapped_keys| に足してください。
>lua
    -- 変換モードの x を <BS> に移す
    skkeleton.register_keymap("henkan", "<BS>", "henkanBackward")
    skkeleton.register_keymap("henkan", "x", "")
<
==============================================================================
フックと変数                                                   *skkeleton-hooks*

|User| イベントで、処理の前後に自分の関数を呼べます。
>lua
    vim.api.nvim_create_autocmd("User", {
      pattern = "skkeleton-mode-changed",
      command = "redrawstatus",
    })
<
skkeleton-initialize-pre                            *skkeleton-initialize-pre*
	最初に使うときに、初期化の前に 1 度だけ実行します。

skkeleton-initialize-post                          *skkeleton-initialize-post*
	最初に使うときに、初期化のあとに 1 度だけ実行します。

skkeleton-enable-pre                                    *skkeleton-enable-pre*
	有効にする前に毎回実行します。

skkeleton-enable-post                                  *skkeleton-enable-post*
	有効にしたあとに毎回実行します。有効にするときにバッファローカルの
	マッピングを退避して、無効にするときに戻しています。自分でマッピング
	を足すときは、このイベントで足してください。

skkeleton-disable-pre                                  *skkeleton-disable-pre*
	無効にする前に毎回実行します。

skkeleton-disable-post                                *skkeleton-disable-post*
	無効にしたあとに毎回実行します。

skkeleton-mode-changed                                *skkeleton-mode-changed*
	モードが切り替わったときに実行します。実行の前に `g:skkeleton#mode`
	を更新します。

skkeleton-handled                                          *skkeleton-handled*
	入力を処理したあとに実行します。実行の前に |g:skkeleton#state| を
	更新します。

                                                          *g:skkeleton#enabled*
g:skkeleton#enabled
	SKK が有効なら true です。

                                                             *g:skkeleton#mode*
g:skkeleton#mode
	今のモードの名前です。無効なときは空の文字列です。|skkeleton.mode()|
	が返す値のうち、有効なときのものと同じです。

                                                            *g:skkeleton#state*
g:skkeleton#state
	最後に処理したときの状態です。表で、次のキーがあります。
	- phase: 入力の段階。"input"（直接入力）、"input:okurinasi"、
	  "input:okuriari"、"henkan"、"escape" のどれか。
	- henkanFeed: 変換ポイントから入力したかなの文字列。

                                                             *g:skkeleton#debug*
g:skkeleton#debug
	真にしておくと、最初に使うときに |skkeleton-config-debug| を真にします。

==============================================================================
インジケータ                                                 *skkeleton-indicator*

入力モードをカーソルの近くの小さなウィンドウに表示します。skkeleton_
indicator.nvim を元にして、skkeleton.nvim に内蔵しました。|skkeleton.setup()|
の `indicator` に表を渡すと設定でき、`false` を渡すと使いません。何も渡さな
いときは、既定の設定で使います。
>lua
    require("skkeleton").setup({
      indicator = {
        hiraText = "あ",
        border = "single",
      },
    })
<
色を変えるときは、`setup()` を呼ぶ前に |skkeleton-highlight| のハイライトグ
ループを定義するか、`HlName` のオプションで既存のグループの名前を指定しま
す。起動後に変えたときは、`require("skkeleton.indicator").refresh()` で反映し
ます。|cmdline-window| では表示できません。

オプションは次のとおりです。各項目は「名前」「既定」「型」の順で、説明が続きます。

eijiHlName、hiraHlName、kataHlName、hankataHlName、zenkakuHlName、abbrevHlName ~
	既定: "SkkeletonIndicatorEiji"、"SkkeletonIndicatorHira"、
	"SkkeletonIndicatorKata"、"SkkeletonIndicatorHankata"、
	"SkkeletonIndicatorZenkaku"、"SkkeletonIndicatorAbbrev"
	型: string
	直接入力、ひらがな、カタカナ、半角カタカナ、全角英数、abbrev の各モー
	ドで使うハイライトグループです。

eijiText、hiraText、kataText、hankataText、zenkakuText、abbrevText ~
	既定: "英字"、"ひら"、"カタ"、"半ｶﾀ"、"全英"、"abbr"
	型: string
	各モードで表示する文字列です。

border ~
	既定: nil
	型: 文字列、配列、または関数
	指定すると枠線を付けます。値は |nvim_open_win()| の `border` と同じ
	か、それを返す関数です。関数は `{ mode = "hira" }` のような表を受け
	取り、モードごとに枠線を変えられます。nil を返すと枠線が消えます。
	関数が nil を返したときは、枠線を指定しないときと違い、枠線の分の
	空白が文字列の周りに残ります。

row ~
	既定: 1（border が nil、"none"、"shadow" 以外のときは 0）
	型: integer
	カーソルを基準にした縦の位置です。

col ~
	既定: 1
	型: integer
	カーソルを基準にした横の位置です。

zindex ~
	既定: nil
	型: integer
	他のウィンドウと重なるときの順序です。|nvim_open_win()| の同名のオプ
	ションと同じです。

alwaysShown ~
	既定: true
	型: boolean
	真なら、挿入モードでは常に表示します。偽なら、SKK が有効なときだけ
	表示します（直接入力の表示は出なくなります）。

fadeOutMs ~
	既定: 3000
	型: integer
	表示が消えるまでの時間（ミリ秒）です。0 なら、挿入モードのあいだ
	ずっと表示します。

ignoreFt ~
	既定: {}
	型: string[]
	表示しないファイルタイプです。

bufFilter ~
	既定: 常に true を返す関数
	型: fun(bufnr: integer): boolean
	バッファの番号を受け取り、true を返すと表示します。ignoreFt のあとに
	評価します。

useDefaultHighlight ~
	既定: true
	型: boolean
	Neovim の既定のカラースキームを使っているとき、自分で定義したハイラ
	イトグループより既定の配色を優先するかどうかです。自分の配色を使い
	たいときは false にします。

ハイライトグループ                                           *skkeleton-highlight*

SkkeletonPreedit                                          *hl-SkkeletonPreedit*
	入力中の文字（pre-edit）の表示に使います。既定では何も指定していな
	いので、周りの文字と同じ見た目になります。
>lua
    vim.api.nvim_set_hl(0, "SkkeletonPreedit", { underline = true })
<
SkkeletonIndicatorEiji                              *hl-SkkeletonIndicatorEiji*
SkkeletonIndicatorHira                              *hl-SkkeletonIndicatorHira*
SkkeletonIndicatorKata                              *hl-SkkeletonIndicatorKata*
SkkeletonIndicatorHankata                        *hl-SkkeletonIndicatorHankata*
SkkeletonIndicatorZenkaku                        *hl-SkkeletonIndicatorZenkaku*
SkkeletonIndicatorAbbrev                          *hl-SkkeletonIndicatorAbbrev*
	インジケータの各モードの表示に使います。自分で定義していないとき
	は、'background' に合わせた既定の配色になります。たとえば Hira は、
	dark では次の配色です。
>lua
    { fg = "NvimDarkGrey2", bg = "NvimLightGreen",
      ctermfg = "black", ctermbg = "green", bold = true }
<
	Neovim の既定のカラースキームを使っているときは、自分の定義より
	既定の配色を優先します。避けるには |skkeleton-indicator| の
	`useDefaultHighlight` を false にします。

FAQ                                                              *skkeleton-faq*

変換ができない~

変換には SKK 辞書が要ります。https://skk-dev.github.io/dict/ の SKK-JISYO.L
などを展開して、|skkeleton-config-globalDictionaries| にパスを書いてください。

初回の変換が遅い~
                                                       *skkeleton-faq-initialize*
辞書は最初に使うときに読み込みます。初めてのときは辞書の DB を作るため、その
あいだ入力が止まります。Neovim を開いたあとで準備しておくには、
|skkeleton.initialize()| を呼びます。
>lua
    vim.api.nvim_create_autocmd("VimEnter", {
      callback = function()
        require("skkeleton").initialize()
      end,
    })
<
DB は UI を止めないように小分けにして作ります。2 回目からは、できた DB を開く
だけです。

DB はどこにあり、どう作り直しますか~
                                                          *skkeleton-faq-database*
`stdpath("cache")/skkeleton`（|skkeleton-config-databasePath| を設定したとき
はそのディレクトリ）に、辞書ごとの `<ハッシュ>.db` があります。辞書の大きさや
更新時刻が変わると、次に使うときに自動で作り直します。すぐに作り直すには、
|skkeleton.update_database()| に {force} を渡します。
>lua
    require("skkeleton").update_database("~/.config/skk/SKK-JISYO.L", nil, true)
<
DB のファイルを消しても構いません。次に使うときに作り直します。

変換ポイントの描画が乱れる~

▽ と ▼ は 'ambiwidth' の対象です。Neovim と端末やフォントの設定が合っていな
いと、描画が乱れます。'ambiwidth' を変えるか、対象外の文字を指定してください。
>lua
    markerHenkan = "▿",
    markerHenkanSelect = "▾",
<
他のプラグインと干渉する~

有効にするときと無効にするときのフックで、他のプラグインの機能を一時的に止め
られます。
>lua
    local group = vim.api.nvim_create_augroup("skkeleton-coc", {})
    vim.api.nvim_create_autocmd("User", {
      group = group,
      pattern = "skkeleton-enable-pre",
      callback = function() vim.b.coc_suggest_disable = true end,
    })
    vim.api.nvim_create_autocmd("User", {
      group = group,
      pattern = "skkeleton-disable-pre",
      callback = function() vim.b.coc_suggest_disable = false end,
    })
<
sticky key の動きを eskk.vim に合わせたい~

skkeleton は sticky key をかなテーブルに置いているので、「察し」を `;sass;si`
と打ちます。eskk.vim のように `;sass;i` と打つには、次のようにします。
>lua
    require("skkeleton").register_keymap("input", ";", "henkanPoint")
<
端末モードで入力が崩れる~

端末バッファでは BS を送って消してから書き直す方法で入力しています。そのた
め、マルチバイト文字の扱いが違うアプリケーションでは、入力が崩れることがあり
ます。コマンドラインで SKK を使って、結果を送る方法もあります。
>lua
    vim.keymap.set("t", "<C-y>", function()
      vim.api.nvim_feedkeys(vim.fn.input(""), "n", false)
    end)
<

skkeleton からの移行                                         *skkeleton-migration*

設定のキーは skkeleton のものをそのまま使えます。呼び出しは次のように変わり
ます。

	skkeleton#config({...})            -> require("skkeleton").setup({...})
	skkeleton#register_kanatable       -> skkeleton.register_kanatable
	skkeleton#register_kanatable_file  -> skkeleton.register_kanatable_file
	skkeleton#register_keymap          -> skkeleton.register_keymap
	skkeleton#initialize()             -> skkeleton.initialize()
	skkeleton#update_database          -> skkeleton.update_database
	skkeleton_indicator の setup({...}) -> setup({ indicator = {...} })

違うところ~
- |skkeleton-config-databasePath| はディレクトリです。skkeleton が作った DB
  のファイルは使わず、新しく作ります。
- `sources` の "deno_kv" は "skk_dictionary" と同じ扱いです。
- skkServer*、completionRankFile は値の確認だけをして使いません。

v1 で使えないもの~
- skkserv と Google 日本語入力（`sources` の "skk_server"、
  "google_japanese_input"）
- ddc の補完ソースと、補完の rank file
- yaml と msgpack の辞書
- `skkeleton#handle()`、`skkeleton#dangerously_clear_buffer_local_mappings()`

同じ Neovim に skkeleton と skkeleton.nvim の両方を入れないでください。
